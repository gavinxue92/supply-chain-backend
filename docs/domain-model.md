# 领域模型图（文字版）

## 模型状态

本模型根据 `CONTEXT.md` 和 ADR-0001 至 ADR-0009 梳理；分类、产品草稿和媒体上传等实现正在按垂直切片落地。业务概念和约束来自已确认需求；实体拆分、聚合边界及限界上下文是供实现使用的领域建模建议，不等同于新的部署或物理模块决策。

### 上下文职责和关系

| 限界上下文 | 拥有的语言与职责 | 与其他上下文的关系 |
|---|---|---|
| **目录管理** | 维护食材产品、规格、图文内容、关键词、分类归属、产品客服挂载及产品生命周期，含归档后硬删除。 | 产品引用媒体资源 ID、分类 ID 和客服联系人 ID；产品客服解析读取客服配置上下文的全局默认列表。 |
| **公开目录查询** | 面向免登录客户提供可见分类、上架产品、详情、搜索和客服列表展示。 | 是目录管理数据的查询视图，不拥有产品生命周期；可由目录管理上下文内的查询端口实现，不要求成为独立部署单元。 |
| **客服配置** | 管理可复用客服联系人及单一运营主体的全局默认客服列表。 | 目录管理在解析“继承全局”策略时读取当前列表；产品挂载列表仍由目录管理拥有。 |
| **媒体资源管理** | 管理图片上传授权、上传确认、元数据登记、引用计数及无引用删除。 | 其他上下文只保存媒体资源 ID；对象存储对象由媒体上下文统一删除。 |
| **后台身份与会话** | 管理后台账号、角色、认证、账号锁定和可撤销会话。 | 业务变更请求携带已认证操作者 ID；本上下文不拥有产品或分类权限之外的数据。 |
| **操作审计** | 追加关键业务操作记录并按约定保留。 | 从已成功的业务操作接收操作者、对象和变更摘要；不接受密码、令牌等认证秘密。 |

上述是逻辑职责边界。它们可以先作为一个后端中的模块实现；需求未决定微服务拆分、消息总线或单独数据库，模型不暗示这些技术选择。

## 实体、值对象与聚合

### 目录管理

**聚合根：食材产品**

- **实体：规格**，在产品内拥有身份；规格名称和参考价属于该规格。
- **值对象：产品名称、图文详情、搜索词集合、产品排序权重**。
- **值对象：产品客服策略**，取值为继承全局、产品覆盖或关闭；覆盖值是一组有序客服联系人引用。
- **值对象：有序媒体引用**，主图为一个媒体资源引用，轮播图为最多八个有序引用，详情中的图片也引用已登记资源。
- **引用：分类 ID**，只指向末级分类，不将分类树作为产品聚合的一部分。
- **终态：硬删除**，只有 ARCHIVED 产品可被管理员硬删除；物理移除产品、规格、关键词、轮播和客服挂载，并释放分类引用。

产品聚合负责自身状态转换和内部约束：草稿、上架、下架、归档。草稿可逐步补充资料；进入上架状态时，必须具备名称、启用末级分类、一张主图和至少一个规格。每个规格的价格可以为空；非空价格须为正且精确到分。引用分类和媒体时，需要应用服务或领域策略验证被引用对象有效。

**聚合根：分类**

- 每个一级或二级分类节点分别作为一个分类聚合根。
- **实体数据**：分类 ID、名称、父分类 ID、启用状态和排序权重。
- 一级分类的父分类 ID 为空；二级分类的父分类 ID 指向一级分类。
- 产品只引用末级分类 ID。父子关系通过 ID 关联，不把所有子分类和产品装进一个大聚合。

分类聚合维护本节点状态。父分类停用对客户可见性的影响由公开查询的分类可见规则求得，不级联修改子分类或产品状态。父分类只能有子分类、不能自身作为产品末级分类；层级最多两级。

### 客服配置

**聚合根：客服联系人**

- 管理员创建、编辑、停用和硬删除；带展示名称、微信号、二维码媒体引用、手机号和启用状态。
- 至少配置微信号、二维码或手机号之一；手机号非登录凭据，可向客户展示。
- 停用后不可被新挂载，公开展示时过滤，既有挂载关系保留。

**聚合根：全局客服配置**

- 作为单一运营主体的默认配置存在，持有一组有序客服联系人引用。
- 配置保存后，继承该配置的产品在下一次查询时解析到新的全局客服列表；覆盖和关闭策略不受影响。

**值对象：产品客服策略**

- `继承全局`：不携带自身客服，解析全局客服列表。
- `产品覆盖`：携带一组有序客服联系人引用；不从全局配置逐字段补齐。
- `关闭`：不展示客服入口。

该策略由食材产品聚合拥有，避免产品级规则被误认为全局设置的一部分。

### 媒体资源管理

**聚合根：媒体资源**

- **值对象：媒体资源 ID、对象键、媒体类型、字节大小、公开访问地址**。
- 上传授权和上传确认构成受控的资源登记流程；媒体资源区分 `PENDING`、`READY`、`REJECTED` 和 `DELETING` 状态。
- 文件格式与大小约束在资源确认时按实际文件内容验证，而不是信任扩展名。
- 产品内容只可引用已登记资源 ID；对象存储对象由媒体上下文统一删除，不由产品聚合直接拥有。
- 删除以引用计数归零为前提；先移除数据库引用/记录并提交，再删对象；对象删除失败保留 `DELETING` 状态待重试。
- `pending/` 对象在确认成功、失败或凭证过期等终态均被清理。

媒体资源聚合负责对象生命周期，避免删除逻辑散落在产品、全局客服和客服联系人中。

### 后台身份与会话

**聚合根：后台账号**

- **值对象：用户名、昵称、密码哈希、后台角色**（管理员或运营编辑）。
- 维护账号启用/停用、首次登录需改密码及连续失败后的锁定状态。
- 密码重置和账号停用要求撤销该账号的既有会话；硬删除还要求物理清除会话并由数据库置空媒体/审计外键。
- 昵称可选、非唯一；管理员和运营编辑可维护自己的昵称，管理员可维护他人昵称。

**聚合根：后台会话**

- **值对象：会话 ID、签发时间、最后活动时间、过期时间**。
- 每个会话关联一个后台账号 ID；允许同一账号存在多个会话。
- 登出撤销当前会话；账号停用或密码重置撤销该账号全部既有会话；空闲 12 小时过期。

将会话单独作为聚合根是为了表达多设备独立撤销；不意味着必须采用特定的 Cookie 存储技术之外的会话数据库实现。

### 操作审计

**聚合根：操作审计记录**

- 记录操作者账号 ID、发生时间、操作类型、目标对象引用及不含秘密的变更摘要。
- 创建后不可变；按约定保留一年。
- 业务操作成功后生成记录；审计写入失败时的事务协调方式需由实现选择，并确保不出现静默丢失记录的成功结果。

## 值对象目录

| 值对象 | 关键约束 |
|---|---|
| **参考价** | 人民币；允许缺省；非空时大于零且精确到分。缺省在展示层表达为「面议」。 |
| **客服联系方式** | 微信号、二维码和手机号均可选，但不能同时缺省；每种最多一个。 |
| **客服手机号** | 可选、非唯一、中国大陆手机号格式；公开展示，不作为身份凭据。 |
| **产品客服策略** | 明确区分继承全局列表、挂载列表覆盖和关闭，不能用空字段混淆三者。 |
| **产品名称** | 上架时必填。具体长度、规范化及唯一性未约定。 |
| **分类名称** | 同一父分类下唯一；不同父分类可重名。 |
| **有序媒体引用** | 上架时主图恰为一个；轮播图最多八个；只引用系统已登记媒体。草稿可尚未配置主图。 |
| **图文详情** | 受限 HTML 经服务端白名单清洗；仅可引用系统媒体资源。 |
| **产品搜索词** | 运营维护的关键词/别名；匹配产品名称和这些词。词条去重与分词策略未约定。 |
| **后台角色** | 管理员或运营编辑；授权边界由 ADR-0007 定义。 |

## 边界场景校验

1. **一级分类停用后重新启用**：一级分类仍为停用时，二级分类即使自身启用且产品已上架，也不可通过公开目录查询；产品与二级分类状态不变。重新启用一级分类后，只有仍启用的二级分类及其仍上架产品恢复可见。
2. **产品挂载多个客服**：`OVERRIDE` 产品只展示自己挂载的客服列表，顺序与挂载一致；不得把全局客服补进来。停用的客服不展示，但既有挂载关系保留。只有 `INHERIT` 才解析当前全局客服列表。
3. **产品归档并恢复**：归档后产品不可公开查询且保留数据；恢复后为下架，需再次检查并上架。归档产品仍计入分类删除和媒体引用约束，直到被硬删除。
4. **归档后硬删除产品**：管理员只能硬删除 `ARCHIVED` 产品；物理移除产品、规格、关键词、轮播和客服挂载，释放分类引用，并清理其独占媒体；删除后不可恢复。
5. **账号停用后硬删除**：管理员不能删除启用中账号、自己或最后一个启用管理员；硬删除前物理清除会话，数据库置空媒体上传者和审计操作者外键，审计摘要保留操作者快照。
6. **替换图片与媒体清理**：替换主图、轮播、二维码或详情图片后，旧媒体若不再被任何未硬删产品、全局配置或客服联系人引用，则删除记录和对象；仍被引用则保留。
7. **未定价规格**：产品有至少一个规格即可满足规格数量条件；价格为空时显示「面议」，不是零元报价。
8. **上传凭证已签发但未确认**：未完成确认登记的图片不能成为产品主图、轮播图、详情图或客服二维码引用；确认终态后清理 `pending/` 对象。
9. **分类删除**：分类仍关联产品或子分类时禁止删除。归档产品仍算引用，直到被硬删除并释放分类引用。
10. **管理员重置密码**：要求首次改密，且旧后台会话应失效；多个终端的旧会话都不能继续操作后台。

## 尚未确认的模型细节

- 产品、规格、分类和关键词的最大长度、排序权重范围、关键词规范化及匹配分词规则。
- 对象存储删除失败后的自动重试机制与告警接入方式；当前仅保留 `DELETING` 状态，不引入消息基础设施。
- “暂时锁定”的具体时长、登录失败计数重置条件和限流阈值。
- 后台账号名及分类名的大小写/空格规范化方式。
- 不含秘密的审计变更摘要粒度，以及审计存储故障时与业务事务的精确协调策略。
- 公开目录查询是否需要独立的持久化读模型、缓存或索引；当前只确认其可观察行为，不预设性能与一致性实现。
