# ADR-0009：数据库部署、容器化与测试策略

- **状态**：已接受
- **日期**：2026-11-16

## 背景

项目从空目录开始，生产云平台尚未选定。开发环境需要可复现，并验证 MySQL 和对象存储交互，而不把测试限制在模拟实现上。

## 决策

- 使用 `scripts/schema.sql` 直接部署数据库结构，不使用 Flyway 或应用启动迁移。Docker Compose 在 MySQL 数据卷首次初始化时执行该 SQL；已有数据库由部署人员手动执行相应 SQL。
- 使用 Docker Compose 本地运行应用、MySQL 和 MinIO；生产交付 Docker 镜像。
- 通过环境配置注入环境差异；对象存储使用 S3 兼容接口。
- 测试以版本化 REST API 的外部行为为最高接缝，覆盖公开浏览、管理权限、目录与客服规则。
- 编写纯业务规则的单元测试，以及 API 集成测试。
- 使用 Testcontainers 启动 MySQL 并直接执行部署 SQL，验证表结构、约束和真实数据库查询；用 MinIO 验证对象存储上传链路。
- 媒体切片的接口集成测试通过 HTTP 调用应用，并由 Testcontainers 提供 MySQL 和 MinIO；若本地 Docker Engine 不可用，应记录阻塞并使用隔离的本地服务执行 HTTP 验收，不能把未运行的容器测试描述为已通过。
- 生成 OpenAPI 3 契约；Swagger UI 仅非生产环境开放。

## 后果

- 本地开发和 CI 可使用与生产接口兼容的数据库/对象存储依赖。
- 当前没有既有代码或测试先例；后续测试先例应从 API 行为及容器化集成测试建立。
- 未确认的云厂商、性能/可用性目标及独立数据库备份要求不属于本决策范围。
