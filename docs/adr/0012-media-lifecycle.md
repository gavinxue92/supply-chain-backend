# ADR-0012：媒体生命周期与删除

- **状态**：已接受
- **日期**：2026-11-19
- **取代关系**：取代 ADR-0005 中“图片删除与孤儿清理尚未指定，不作为首期验收要求”

## 背景

对象存储中的图片持续增加，原因是确认上传后 `pending/` 对象未清理，且替换或删除业务数据后旧图片仍保留。需要让 MinIO 只维护系统仍在使用的图片。

## 决策

- 媒体删除以引用计数归零为前提。引用来源包括所有未硬删产品（草稿、下架、归档均计入）的主图、轮播、详情 HTML 图片，以及全局客服与客服联系人的二维码。
- 触发点：显式 `DELETE /api/v1/admin/media/{id}`、替换产品图片/二维码、产品硬删除。被引用媒体显式删除时返回 `409`。
- 显式媒体删除对管理员和运营编辑开放；服务层负责引用检查，数据库 `RESTRICT` 外键作为最后防线。
- 删除顺序为：先移除数据库中的引用或记录并提交，再删除 MinIO 对象；对象删除失败时保留 `DELETING` 状态并记录日志，不回滚已完成的业务删除，由后续重试清理。
- 上传确认成功或失败时立即清理本次 `pending/` 对象；凭证过期而未确认的 `PENDING` 记录由同服务的定时清理任务扫描并删除对象与记录，不引入消息基础设施。
- 新增审计动作：`MEDIA_RESOURCE_DELETED`。

## 后果

- 公开接口不会指向已删除对象；失败窗口内可能出现短暂孤儿对象，但不能产生断链。
- 媒体实体最终物理删除，`DELETING` 仅用于对象删除失败后的待重试状态。
- 需要服务层统一维护引用计数，不得把对象删除逻辑散落在各个业务 Service 中。
