# ADR-0007：后台身份、会话与请求防护

- **状态**：已接受（部分被 ADR-0010 取代）
- **日期**：2026-11-16
- **更新**：账号昵称、停用后硬删除与审计操作者快照见 ADR-0010；登录、会话和请求防护规则继续有效。

## 背景

运营后台由多名人员使用，需将账号管理与产品编辑权限区分。浏览器后台采用 Cookie 会话时，写接口还需防范跨站请求。

## 决策

- 使用唯一用户名和密码登录，不开放公开注册；本地开发通过 `scripts/init-local-admin.sql` 插入一个要求首次登录改密的临时管理员。生产环境不得使用本地共享凭据，管理员账号由部署方单独建立。
- 管理员可以创建、停用账号并重置密码；被重置账号首次登录须修改密码。
- 管理员可管理账号、全局客服和所有业务数据；运营编辑只能管理产品、分类和产品客服。
- 采用可撤销的 HttpOnly、Secure、SameSite Cookie 会话，支持多设备登录，空闲 12 小时过期。
- 登出、账号停用或密码重置时撤销相关会话。
- 写接口启用 CSRF 防护，并将跨域来源限制为配置的后台域名。
- 登录接口限流；连续密码错误五次后暂时锁定账号，锁定时长可配置。
- 管理员重置密码，不接入短信或邮件自助找回。

## 后果

- 所有管理写操作必须同时通过身份认证、角色授权和 CSRF 校验。
- 本地种子账号仅用于开发环境，凭据为公开临时凭据且首次登录必须改密；不得在生产环境执行本地种子脚本。
- 允许多设备登录意味着会话需可独立撤销；账号停用和密码重置必须使既有登录状态失效。
- 具体密码哈希算法与限流阈值除已确认的连续五次失败外，应采用框架成熟安全方案并由实现明确记录。
